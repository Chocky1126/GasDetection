# 基础资料管理闭环设计

## 目标

在现有第一阶段平台上，把人员、班组、区域、基站、用户和角色从只读列表升级为可实际维护的管理工作台，并让所有新增、修改、删除操作进入统一操作日志。

本轮连续交付三组能力：

1. 人员与班组管理。
2. 区域与基站管理。
3. 用户与角色权限管理。

## 现状

- 六个后端模块已有基础 CRUD 接口。
- 人员已经通过 `PersonnelTeam` 支持多班组关联。
- 基站已经关联区域，用户已经关联角色，角色已经关联权限。
- 六个管理页面仍使用 `SimpleResourceView`，只能刷新和查看列表。
- 基础资料变更没有写入 `AuditLog`。
- 用户和角色列表没有统一分页、关键词检索，前端也没有权限字典接口。

## 方案选择

采用“轻量配置化管理框架 + 领域服务独立事务”的方案。

前端把 `SimpleResourceView` 替换为 `ResourceManagementView`。框架统一处理关键词检索、分页、创建/编辑弹窗、删除确认、表单校验和反馈；各页面只提供字段、列、关联选项和少量序列化规则。

不采用六套完全复制的页面，避免重复维护；也不引入 schema 表单库或低代码依赖，保持 Vue 3 + Element Plus 的现有技术边界。

后端不抽象通用 CRUD 服务。每个领域服务继续拥有自己的关联写入、保护规则和审计详情，所有数据变更与 `AuditLog` 在同一 Prisma 事务中完成。

## 前端管理框架

新增：

```text
apps/admin-web/src/components/ResourceManagementView.vue
apps/admin-web/src/components/resource-management.types.ts
```

支持的字段类型：

```text
text
password
textarea
number
select
multi-select
switch
```

统一工作流：

```text
进入页面 -> 加载分页列表 -> 关键词查询
新增 -> 校验 -> POST -> 成功提示 -> 刷新列表
编辑 -> 回填关联字段 -> 校验 -> PATCH -> 成功提示 -> 刷新列表
删除 -> 二次确认 -> DELETE -> 成功提示 -> 刷新列表
```

组件允许页面提供：

- `columns`：列定义和格式化函数。
- `fields`：表单字段、选项、数值边界、创建/编辑必填规则。
- `initialValues`：新增表单默认值。
- `toForm`：把列表行转换成编辑表单，例如提取 `teamIds`、`roleIds`。
- `toPayload`：提交前删除空密码等不应发送的字段。

## 第一轮：人员与班组

人员页面：

- 关键词搜索人员编号或姓名。
- 查看编号、姓名、电话、岗位、所属班组。
- 新增和编辑时可多选班组。
- 删除前二次确认。

班组页面：

- 关键词搜索班组编号或名称。
- 查看编号、名称、成员数量和说明。
- 支持新增、编辑、删除。

后端变更：

- 人员和班组的 `CREATE`、`UPDATE`、`DELETE` 在同一事务写入 `AuditLog`。
- Controller 从 JWT 用户读取 `user.id` 并传入服务。

## 第二轮：区域与基站

区域页面：

- 查看和维护编号、名称、风险等级、经纬度和说明。
- 风险等级限制为 1 到 5。

基站页面：

- 查看和维护编号、名称、所属区域、经纬度和井下深度。
- 所属区域使用区域下拉选择，不手工输入 ID。

后端变更：

- 区域和基站的 `CREATE`、`UPDATE`、`DELETE` 在同一事务写入 `AuditLog`。
- Controller 传递当前用户 ID。

## 第三轮：用户与角色

用户页面：

- 关键词搜索用户名、姓名、电话或邮箱。
- 查看用户名、姓名、角色、联系方式和启用状态。
- 新增用户时密码至少 6 位。
- 编辑时密码留空表示不修改密码。
- 支持多角色分配和启用状态切换。
- 禁止删除当前登录用户。

角色页面：

- 关键词搜索角色名或说明。
- 查看角色、说明和权限数量。
- 权限按“模块 / 权限名”展示并支持多选。
- 禁止删除内置 `admin` 角色。

新增接口：

```text
GET /api/v1/roles/permissions
```

用户和角色列表统一返回：

```text
{
  items: [],
  total: number,
  page: number,
  pageSize: number
}
```

## 操作日志

模块值：

```text
personnel
teams
areas
base-stations
users
roles
```

动作值：

```text
CREATE
UPDATE
DELETE
```

审计记录保存当前用户 ID、资源 ID 和可读详情。数据库写入失败时，业务变更一并回滚。

管理端操作日志筛选补充上述六个模块。

## 错误处理

- DTO 校验失败：400。
- 用户名或角色名冲突：409。
- 用户或角色不存在：404。
- 删除当前用户：400。
- 删除内置 `admin` 角色：400。
- 关联资源导致数据库拒绝删除：沿用统一异常响应，不伪造成功状态。
- 前端保存失败时保持弹窗内容，展示错误提示。

## 测试与验收

后端单元测试覆盖：

- 六个领域的创建、更新和删除审计事务。
- 人员班组关联替换。
- 用户分页关键词查询和角色分配。
- 当前用户不能删除自己。
- 角色分页关键词查询、权限字典和权限替换。
- 内置 `admin` 角色不能删除。

全量验证：

```bash
pnpm -r typecheck
pnpm -r test
pnpm -r build
./scripts/docker-up.sh
```

浏览器验收：

- 六个页面均可完成查询、打开新增/编辑弹窗和删除确认。
- 至少分别创建并编辑一条人员、区域和用户测试数据。
- 操作日志能按对应模块查到记录和操作人。
- 页面无控制台错误、布局溢出或遮挡。

## 非目标

- 本轮不新增组织树、排班、考勤或用户在线会话管理。
- 本轮不做权限继承、角色层级和字段级权限。
- 本轮不改变数据库实体关系。
- 本轮不接入真实硬件或外部身份系统。
